# Как вести репозиторий

Хакатон завершён, код больше не пишется — но репозиторий остаётся в рабочем
состоянии: чтобы любой мог его прочитать, воспроизвести и понять, почему в нём
такие решения.

## Один эксперимент — одна карточка

**Правило №1.** Один эксперимент = одна запись `expNN` в
[EXPERIMENTS.md](EXPERIMENTS.md) + один каталог в `archive/expNN/`.

Порядок жизни эксперимента:

1. **Гипотеза сформулирована и критерий adoption зафиксирован ДО запуска.**
   Без критерия результат не считается — его придётся подгонять постфактум.
2. Код живёт в `src/`, отчёт — в `reports/`.
3. После закрытия (`done` / `rejected`) код и отчёты переезжают в
   `archive/expNN/{src,reports,submissions}`, и в журнале появляется карточка.

Исторические имена (`b01`, `b03`, `b05`, `e2`, `stack`, `exp025`) сохраняются
как алиасы в заголовке карточки.

### Что значит «закрыт»

| Статус | Когда |
|---|---|
| `planned` | гипотеза есть, код не написан |
| `running` | идёт прогон |
| `done` | результат получен, вывод сделан |
| `rejected` | результат получен, направление закрыто |
| `data ready` | датасет фичей собран, обучение не начиналось |
| `priors ok` | калибровочные артефакты готовы, обучение не начиналось |
| `infra` | построена инфраструктура, прогоны не сохранялись |
| `not run` | скрипт готов, запуск не выполнялся |

`done` и `rejected` — оба закрывают эксперимент: в обоих случаях код
уезжает в архив.

## Куда что класть

| Хочу положить | Куда |
|---|---|
| Код нового эксперимента | `src/` |
| Отчёт нового эксперимента | `reports/` |
| Закрытый эксперимент (код + отчёты) | `archive/expNN/` |
| Правило, верное независимо от эксперимента | `docs/` |
| Открытую гипотезу, идею, разбор | `notes/` |
| Результаты всех экспериментов | `EXPERIMENTS.md` |
| Крупный артефакт (parquet, CSV-сабмит, чекпоинт) | **не в git** — регенерируется скриптом |

Правило «каждый эксперимент владеет своими артефактами»: отчёт закрытого
эксперимента лежит в `archive/expNN/reports/`, а не в общем `reports/`.
Корень `reports/` — только для активных экспериментов.

## Код

- **Пути** — только через `src/common/paths.py`. Скрипт должен запускаться из
  любого каталога. Скрипты в `archive/` — исключение: это замороженная
  история, они работают на относительных путях от корня репозитория.
- **Запуск из корня** — для архивных скриптов это обязательное условие.
- **Сид 42**, один набор фолдов, никакой информации после якоря — см.
  [docs/PROTOCOL.md](docs/PROTOCOL.md).

## Перед коммитом

```bash
git status                      # мусора быть не должно
python -m compileall src        # синтаксис
ruff check src && ruff format --check src
```

В репо не должно быть мусора: `__pycache__`, `.DS_Store`, `catboost_info/`,
логи, временные файлы, чекпоинты, тяжёлые parquet и CSV-сабмиты.

Хуки: `pre-commit install` — один раз, дальше они срабатывают сами.

## Коммиты

- Один коммит — одно осмысленное изменение.
- Сообщение в стиле репозитория: `feat(expNN): …`, `fix: …`, `docs: …`,
  `chore: …`.
- Коммит с результатом эксперимента содержит и код, и карточку в журнале.
