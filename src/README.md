# `src/` — что здесь живёт

В `src/` лежит только то, что **развивается или переиспользуется**. Закрытые
эксперименты целиком переезжают в `archive/expNN/` — вместе с кодом, отчётами и
сабмитами. Правило зафиксировано в [CONTRIBUTING.md](../CONTRIBUTING.md).

## Активные скрипты

| Файл | Назначение | Эксперимент |
|---|---|---|
| `eda.py` | EDA сырых данных: целостность, таргет, сезонность, интент-сигналы. Пишет `reports/eda.md` | — (инфраструктура) |
| `build_features_ext_pca.py` | Фичевые датасеты `data/v2/features_ext`: base70 + x_\*28 + pca32. ~4 мин | exp02, exp07 |
| `build_features_bgnbd.py` | BTYD-фичи (BG/NBD + Gamma-Gamma) → `data/v2/features_bgnbd`. ~1 мин | exp04 |
| `exp03_hurdle_priors.py` | Приоры хёрдла: P(buy) и E[z\|buy] по сегментам рекенси×интент | exp03 (не завершён) |
| `exp1000.py` | Фабрика экспериментов: 1006 приоритизированных конфигов, параллельный пул | exp09 (инфраструктура) |
| `exp11_global_lags.py` | Глобальная модель на лагах (M5-style pooled) | **не заведён в журнал** |
| `train_btyd.py` | Соло-диагностика BTYD через пакет `lifetimes` (E[GMV] как предикт) | exp04 (диагностика) |
| `common/paths.py` | Единая точка правды для путей: `REPO_ROOT`, `DATA_DIR`, `REPORTS_DIR`, … | — |

## Правило путей

Скрипты **не зависят от текущего рабочего каталога**: все пути строятся от
корня репозитория через `common.paths`. Скрипт можно запускать откуда угодно:

```bash
.venv/bin/python /path/to/ozon-ecup/src/eda.py
```

Скрипты в `archive/` — замороженная история: они используют относительные пути
и предполагают запуск **из корня репозитория**.

```bash
.venv/bin/python archive/exp15/src/train_stack_v2.py
```

## Два файла вне журнала

- **`exp11_global_lags.py`** — написан до перехода на сквозную нумерацию
  `expNN`, поэтому его внутреннее имя «exp11» **не совпадает** с журнальным
  exp11 (это PLSI-CAL STL, alias `b03`). Эксперимент не запускался в
  воспроизводимом виде, отчёт `reports/exp11_global_lags.json` не сохранён.
  Файл оставлен как есть; завести ему карточку в журнале — открытый вопрос.
- **`train_btyd.py`** — соло-диагностика BTYD из карточки exp04
  (`bgnbd_e_gmv30 2.64`, `eb_e_gmv30 2.43`). Требует пакет `lifetimes`,
  который не входит в `requirements/base.txt` — ставится отдельно.
